# Draft recovery and command-size experiments

The command-size correction applies to ordinary builds. Draft recovery is an optional experiment, disabled unless the build includes `VITE_REMOTE_EXPERIMENTS=drafts`. The user must additionally choose “Remember drafts on this device” for the authenticated computer scope. An ordinary build neither reads nor offers recovery.

## Command sizing

The browser measures UTF-8 bytes of the complete JSON command. Managed transport includes its outer `{id, method, body}` envelope. The limit is 256 KiB; UUID placeholders have exactly the generated UUID length. Both `prompt` and `sendNow` reject oversized payloads before network dispatch and before registering a pending receipt. A defensive transport check covers direct transport consumers, and HTTP 413 is reported as a definite refusal.

The composer checks the complete proposed draft, including previous text and multiple selected files, before inserting attachments. It preserves text when the message is too large. A delayed file read cannot overwrite intervening edits or insert into another conversation. Image/binary content remains encoded text, not multimodal input; the interface says so. The independent per-file read cap remains 200 KB and the per-pick raw total cap 600 KB. Passing those read caps alone does not imply the complete command fits.

Regression tests first failed for oversized prompt and sendNow. Exact-boundary tests cover limit−1, limit, limit+1, Unicode, JSON escaping, the 200 KB image regression, accumulated text/files and no pending-receipt registration for a rejected command.

## Storage and identity

Managed recovery requires authenticated account ID plus host ID, pinned host public key and installation ID. Private HTTPS recovery requires optional installation ID in the authenticated pair/resume result, its browser pairing ID and the current origin. The Grok conversation ID is an additional per-record key. Older private hosts without installation metadata do not offer recovery. No loopback port or public health probe is treated as installation identity.

Records are in IndexedDB database `grok-remote-drafts.v2` on this browser profile. Every transaction requests `durability: "strict"`; a browser that cannot confirm that mode fails visibly. The interface says Saving while the current edit is pending and Saved only after transaction completion. Consent and the initial draft snapshot commit atomically. They contain unsent text, including any attachment text, and are not encrypted separately at rest. They are not written to the service-worker shell cache or transmitted to an account service. Only the last successfully saved edit is recoverable. Writes exceeding storage quota or a 1 MiB local draft ceiling leave current text in memory and show an error. They never silently truncate or send.

Writes preserve invocation order and the hook coalesces edits queued behind an active write to the latest text per session. Pending edits and the initial consent snapshot have a 64-session/4-MiB ceiling; a draft has its separate 1-MiB UTF-8 ceiling. The storage scheduler permits at most 64 operations, reserving one slot for deletion. Deletion invalidates obsolete queued work and concurrent deletions for a scope join the same operation. Historical stored drafts are bounded by browser quota and expiry, not a claimed aggregate 4-MiB limit.

A draft expires seven days after its last successful write. Expired, malformed and future-dated records are removed when that scope is next read; a closed browser cannot run a timed erasure. Explicit opt-out deletes stored drafts in the selected scope while preserving current unsent text in the open page. Confirmed revocation/forgetting also clears in-memory text and disables persistence. Other scopes remain intact. A remote revocation cannot be known while the browser is offline; cleanup occurs after the browser receives the refusal. New authenticated private pairing metadata replaces and deletes the former scope. Storage denial can prevent physical deletion; the interface does not claim cleanup succeeded in that case.

Each consent generation has an opaque epoch. Writes from an older generation fail after deletion and re-enabling. Revocation clears the current page immediately; cross-tab notifications are sent after the deletion commits and identify the deleted epoch, so a delayed notification cannot erase text from newer consent. Async reads and write completions cannot overwrite edits made while recovery was pending or update a different account scope. A successful older write never marks a newer refused edit as Saved.

Valid, consented v1 localStorage drafts migrate once in a strict transaction. Legacy entries are removed only after its commit. A persisted disabled scope prevents old localStorage content from resurfacing even if legacy removal was denied. Storage failures retain current in-memory text and never automatically send a prompt.

## Evidence and qualification

Service tests cover consent, identity isolation, seven-day boundary, corruption, storage rejection, exact-scope deletion and stale-tab writes. React integration tests cover opt-in, component remount, scope switching, deletion and recovery without any prompt/sendNow dispatch. Client tests verify private identity comes from authenticated pair/resume and that a replacement pairing removes the old namespace. Application tests recover a saved conversation draft after unmount/remount with zero automatic sends.

The independent browser process-death test found two failures in the original localStorage implementation: the browser could lose text previously reported as saved. Those failures remain in the evidence. The replacement uses strict IndexedDB transactions and an accurate save acknowledgement. In `draft-recovery-04/report.json`, Chrome was killed with SIGKILL 3 ms after observing the final saved edit; a new process with the same profile and origin recovered the exact last text and consent. That run also verified a real service-worker update, old-shell cleanup, offline recovery, seven-day expiry, injected IndexedDB quota failure, and zero automatic sends: nine checks with no uncaught browser errors.

This is a desktop Chrome proof with synthetic host transport. It does not establish Android process eviction, actual durability after device power loss, production OAuth/TLS or Tailscale, assistive-technology accessibility, or usefulness to a person. Those remain separate acceptance criteria. The experiment remains off by default pending them.

The sealed source in `durable-drafts-source-01/source-manifest.json` passes 650 tests across 59 files and TypeScript checks. `combined-fixture-05` was built from that frozen copy; its browser workflow passes 20 checks and its mobile layout/default-off workflow passes five. `frontend-artifacts-durable-01.json` binds those tests, the source, process-death report and ordinary/experimental Remote artifacts by hash. The independent review caught and the tests now detect obsolete-write acknowledgements, deletion barrier ordering, duplicate deletions and obsolete consent completions. `managed-browser-02/report.json` additionally passes 18 checks through the actual PWA, account service, Noise, relay and native host with synthetic sessions on three hosts and two accounts, including account/host switching and selective revocation. `drafts-final-02/identity-join.json` verifies all 145 product source/build inputs match the frozen draft candidate. All nine draft acceptance checks now pass; `drafts-final-02/result.json` remains inconclusive because participant benefit/usefulness has not been measured. The managed fixture uses loopback HTTP and synthetic sessions, so production OAuth/TLS, Tailscale and Grok inference are not qualified by this result. All paths name evidence under `/tmp/grok-remote-evaluation-ter17my1`; no deployment was performed.
